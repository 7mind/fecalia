# Adaptive-policy scenario 1a: radio survivor budget

Observed baseline: detached worktree at `f75668e`. The temporary test below
uses that commit's deterministic `voiceThroughOutage` model, with saturating
bulk and two 50 Hz voice streams in each direction on the sole 0.4 Mbit/s
survivor. It measures the final five seconds after ten seconds of warmup;
there is no loss, jitter or external TCP ACK stream. Encrypted bulk datagrams
are counted before TCP, so TCP payload cannot exceed this delivery.

Reproduce by adding this file as `internal/bond/adaptive_policy_budget_test.go`
to a worktree at `f75668e`, then running:

```sh
nix develop --command go test ./internal/bond -run TestAdaptivePolicy1aRadioSurvivorBulkGate -count=1 -v
```

```go
package bond_test

import (
    "testing"
    "time"
)

func TestAdaptivePolicy1aRadioSurvivorBulkGate(t *testing.T) {
    const survivorBytesPerSecond = 50000
    delivered, sent, p99, gap, bulk := voiceThroughOutage(t,
        []float64{survivorBytesPerSecond},
        []time.Duration{20 * time.Millisecond},
        []time.Duration{0}, 0, -1, 0, 0)
    t.Logf("voice delivered %d/%d, one-way p99 %s, gap %s; bulk bytes/s %v", delivered, sent, p99, gap, bulk)
    for second, bytes := range bulk {
        if bytes < survivorBytesPerSecond*75/100 {
            t.Errorf("scenario 1a radio survivor: second %d bulk %d B/s < 75%% of survivor (%d B/s)", second, bytes, survivorBytesPerSecond*75/100)
        }
    }
}

```

The observed underutilization does not establish why the policy underutilizes
this survivor. Independently, conservation of wire bytes proves the combined
gate cannot be satisfied, even by an ideal scheduler:

- Observed profile: `test/vm/profiles/radio.json`, edge WAN1 = 0.4 Mbit/s,
  or 50,000 B/s.
- Observed model payload: `voiceWireGuardBytes` = 224; observed wire format:
  `bond.Overhead` = 101, outer IPv4/UDP = 28.
- Inferred voice demand: `2*50*(224+101+28)` = 35,300 B/s.
- Inferred upper bound with no voice loss: other traffic <=14,700 B/s.
- Documented scenario 1a requirement: bulk >=37,500 B/s within three seconds,
  while preserving the voice gate. Bulk overhead and ACK traffic only tighten
  the bound.

Over the 15-second outage, even allowing no bulk for its first three seconds,
voice needs 529,500 bytes and bulk needs 450,000 bytes. The survivor can carry
750,000 bytes. Allowing bulk would require losing at least 651 of the 1,500
voice datagrams offered during the outage. That exceeds 8% of all 8,000
datagrams in this direction during the runner's 80-second blackout run,
against the under-1% gate. This bound ignores bulk overhead and feedback.

This concerns sustained delivery on the required radio survivor, not the
aggregate rate with both WANs available. Scenario 1c has the same bound for
this direction. A transient buffer release cannot sustain the stated rate
through a 15-second outage. No policy correction can remove this budget
conflict without changing the required traffic, capacity or acceptance gate.
The gates and wire format remain unchanged. Stages 1–3 were not started.
