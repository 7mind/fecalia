## Remaining test defect

The documented fail-first race gate is nondeterministic:

```text
nix develop --command go test -race -tags failfirst \
  -run '^TestFailFirstFEC' -count=5 ./internal/bind
```

`TestFailFirstFECSendPublishesOneOwnerCommandForLargeBatch` can fail because
`internal/bind/fec_sender_staging_failfirst_test.go:982-986` polls outer
sequence for a fixed 100,000 scheduler yields without asserting that admission
257 opened the partial tail group, then advances the fake clock and signals
once. If the tail opens afterward, it receives a new deadline and `Send` never
resolves. Cleanup writes `owner.afterPublish=nil` at line 978 while
`fecSendOwner.publish` reads it at `internal/bind/fec_sender.go:197`, producing
a race-detector report after the timeout.

Required correction: synchronize on an `afterAdmit` signal for final index 256
before advancing the clock, and clear hooks only after the publisher/Send has
completed. Repeat the fail-first race gate rather than relying on one pass.
